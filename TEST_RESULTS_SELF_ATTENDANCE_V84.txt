LSO SELF-ATTENDANCE MONITORING (V84)
VALIDATION RESULTS
Date: 2026-09-19

RESULT: 32/32 INTERFACE CHECKS PASSED
RESULT: 28/28 DATABASE MIGRATION CHECKS PASSED

Method (interface): the real production page (index.html) was loaded with the
real scripts in a headless DOM, signed in through the real login form against
the Supabase RPC shim, and driven as three different accounts. The seeded
database gave the signed-in Trainee three attendance records (Present, Late,
Excused/LOA) while two other members held two further records, so any leak of
another member's row would fail the run. Harness: self-attendance-audit/harness.js
Reproduce: node self-attendance-audit/harness.js

Method (database): LSO_SELF_ATTENDANCE_MONITORING_V84.sql was executed on a real
PostgreSQL server through the exact V82 -> V84 sequence, including an
already-saved Trainee/Probationary configuration, a removed grant, and a re-run
of the patch. Harness: the embedded-postgres runner documented in the guide.

LIMITS OF THIS VALIDATION

  schema mirror (LSO_V82_ROLE_SYNC_SUPABASE_PATCH.sql -> V84), not on the live
  Supabase project. The patch itself is unchanged by that substitution.
- Appearance should still be confirmed once, on a real device, after upload:
  Trainee/Probationary login -> My Attendance.
