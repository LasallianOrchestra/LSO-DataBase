LASALLIAN SYMPHONY ORCHESTRA — ADMIN CREATE FIX (V90)
=====================================================

SYMPTOM
-------
Signed in as Administrator, nothing can be created or saved: members,
activities, attendance, duty hours, monthly reports, settings, instruments,
and activity-log entries all stay unchanged or show a database error.

ROOT CAUSES FOUND
-----------------
1. MISSING COLUMN: system_state.column_versions
   The base installer (supabase-setup.sql) and the master migration installer
   define public.lso_update_state_v69 against system_state.column_versions but
   never create that column. PostgreSQL rejects every write with 42703:
   column "column_versions" does not exist.

2. WRONG ACCOUNT ROLE CONSTRAINT
   The merged Duty Hours installer resets lso_accounts_role_check to only
   Administrator / Staff Account / Trainee-Probationary. Membership and
   General Secretary accounts therefore cannot be created or approved
   (23514), and re-running the installer fails when those accounts exist.

3. NO ADMINISTRATOR BYPASS IN lso_role_can()
   Older installers define lso_role_can() by reading lso_role_permissions only.
   Administrator has no rows in that table, so its writes are rejected with
   42501 "This account role cannot update the selected system area."

WHAT TO RUN
-----------
EXISTING PROJECT (website can already sign in):
  Run LSO_SUPABASE_REPAIR_V90.sql in Supabase Dashboard -> SQL Editor.
  It is safe to re-run and preserves every account and shared record.

NEW PROJECT OR MISSING BASE TABLES/FUNCTIONS:
  Run LSO_SUPABASE_REWRITE_V90.sql in Supabase Dashboard -> SQL Editor.
  It is the complete, rewritten installer. It is idempotent and safe to re-run.

Then run LSO_SECURE_ADMIN_SETUP.sql privately once to create or rotate the
Administrator credentials, and deploy the website files.

IF THE REPAIR FAILS WITH 42883 (function ... does not exist)
  The repair creates every lso_% function in dependency order, so a helper is
  always created before the function that calls it. If you edited the file or
  regenerated it from pg_get_functiondef, keep that order. PostgreSQL validates
  SQL-language function bodies at CREATE time; creating
  lso_v82_columns_for_actions before lso_v89_columns_for_actions fails with
  42883 on a project that does not already have the helper.

  The repair also restores the complete installer's privilege matrix: 42
  functions are executable by anon/authenticated, and the 10 internal helpers
  (lso_admin_account, lso_apply_default_role_configuration,
  lso_default_role_configuration, lso_session_account_id,
  lso_trainee_scoped_state_v85, lso_v82_columns_for_actions,
  lso_v82_write_role_configuration, lso_v89_columns_for_actions,
  lso_v89_repair_role, lso_v89_write_role_configuration) stay revoked from
  browser roles.

ROLE PERMISSIONS CANNOT BE SAVED ("Assign at least one visible module")
  Cause: LSO_MASTER_MIGRATION_INSTALLER.sql deletes every role's "view" rows
  and re-inserts them only for Staff Account and Administrator. On a project
  that already had lso_role_profiles rows, its default-configuration step is
  skipped, so Membership, General Secretary, and Trainee/Probationary end with
  zero visible modules. The permission center then shows nothing to select and
  every save is rejected with 22023.

  Fix: the master installer now seeds the baseline views for every role, and
  LSO_SUPABASE_REPAIR_V90.sql heals existing projects by calling
  lso_v89_repair_role() for all four configurable roles. The repair's JSON
  result now reports:
    roles_with_views           4
    all_roles_have_views       true
    all_roles_landing_valid    true
    role_views                 { role: [modules...] }
  Re-run LSO_SUPABASE_REPAIR_V90.sql, refresh the page, and open System
  Administration -> Role Management.

WEBSITE-SIDE SAFETY NET
-----------------------
cloud-staff-v8.js now:
  * treats the Administrator as always writable, even if a stale permission
    payload says otherwise;
  * falls back from lso_update_state_v69 to lso_update_state when the V69
    writer fails because column_versions is missing (42703);
  * uses the Administrator-only lso_replace_state writer as a last resort when
    an older lso_role_can() rejects the Administrator (42501).
role-access-v6.js and permissions-dynamic-v38.js also treat the Administrator
as immutable, so a bad role row cannot hide the Add Member / Add Activity
controls.
