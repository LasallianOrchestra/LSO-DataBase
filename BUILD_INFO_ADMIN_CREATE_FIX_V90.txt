LSO Administrator Create Fix — V90
Build: 2026-11-24 admin-create-fix-v90

Purpose:
- Repair the shared Supabase database so the Administrator can create and save
  members, activities, attendance, duty hours, monthly reports, settings,
  instruments, and activity-log entries.
- Restore the five-role account model (Administrator, Staff Account,
  Membership, General Secretary, Trainee/Probationary).
- Make Administrator permissions immutable in the website permission engine.

Root causes corrected:
- system_state.column_versions was referenced by lso_update_state_v69 but never
  created by the base/master installers (42703 on every save).
- The merged Duty Hours installer reset lso_accounts_role_check to three roles,
  blocking Membership and General Secretary accounts (23514).
- Older lso_role_can() definitions had no Administrator bypass (42501).

Database files:
- LSO_SUPABASE_REPAIR_V90.sql   — targeted repair for an existing project.
- LSO_SUPABASE_REWRITE_V90.sql  — complete rewritten installer for a new or
                                  partially installed project.

Website files:
- cloud-staff-v8.js
- role-access-v6.js
- permissions-dynamic-v38.js
- lso-system-core-v4.js

Additional repairs:
- Role permissions could not be saved on a base + master project: the master
  installer deleted every role's "view" rows and re-inserted them only for
  Staff Account and Administrator, so Membership, General Secretary, and
  Trainee/Probationary had zero visible modules and every save failed with
  22023 "Assign at least one visible module". The master installer now seeds
  the baseline views for every role, and the repair heals existing projects
  with lso_v89_repair_role(). The repair verification now reports
  roles_with_views, all_roles_have_views, all_roles_landing_valid, and
  role_views.
- LSO_SUPABASE_REPAIR_V90.sql now creates every function in dependency order.
  The previous alphabetical order created lso_v82_columns_for_actions (a
  SQL-language wrapper) before lso_v89_columns_for_actions, so on a project
  that did not already have the helper PostgreSQL rejected the file with
  42883: function public.lso_v89_columns_for_actions(text[]) does not exist.
- Both the repair and the master installer now reproduce the complete
  installer's privilege matrix: 42 functions executable by anon/authenticated,
  and the 10 internal helpers revoked from browser roles.
- LSO_MASTER_MIGRATION_INSTALLER.sql now also installs the V69 notification
  preferences table, the V69 notification/collection/state-meta RPCs, the V82
  sync-health RPC, and lso_trainee_scoped_state_v85, so supabase-setup.sql +
  master installer is a complete path (52/52 functions).
- The website schema target now matches the migration the server reports
  (009_dynamic_role_permissions), removing a false "run the installer" warning.

- Attendance roster rebuild audit: 0 spurious renders, no errors.
